# 10 — Dependencies & Distribution

Goal: MoonClip runs on **any PC** — AMD, Intel or NVIDIA, with or without a
GPU, software compositing or accelerated — and never *requires* a vendor
codec, NVENC or a proxy step. Everything here is either shipped in the
bundle or is an optional accelerator; the app must stay fully usable when
none of the optional parts are installed.

This is the document the Settings decode notice links to: the UI only shows
the **package name** to install, never a distro command (the app must not
guess the user's package manager); the commands live here.

## 1. What ships in the bundle

| Component | What it is | System libs |
|---|---|---|
| `moonclip` | The Tauri app (Rust + WebKitGTK webview) | distro libs (GTK/WebKit) |
| `engine/bin/moonclip-engine` | Embedded OBS engine (capture/encode/mux) | ~270 direct libs |
| `engine/lib64/engine-plugins/*.so` | Capture, encoder and websocket plugins | adds more on top |
| `ffmpeg-<triple>` | Sidecar: thumbnails, faststart remux, preview/export | 7 (nearly static) |

The **bundled ffmpeg is nearly static** (7 system libs): all software
decoders (`avdec_h264`, `avdec_h265`, `dav1ddec`, `openh264dec`) and the
x264 CPU encoder are compiled in, so playback and export work on a machine
with no GPU driver at all. The engine is the opposite: it links the distro
Qt/PipeWire/Mesa stack, which is why the table below is long.

## 2. Required system libraries

plugins and ffmpeg; provider names come from the local package database

after any engine update.

## 3. Optional: hardware video decode (playback)

MoonClip plays clips through WebKitGTK, which decodes via **VA-API** when a
driver is present and falls back to the bundled software decoders when it
is not. Hardware decode lowers CPU usage on big clips; it is never a
requirement.

The app checks for the vendor driver file in the standard DRI directories
(`/usr/lib64/dri`, `/usr/lib/x86_64-linux-gnu/dri`, `/usr/lib/dri`) and
shows `Decode: Software` plus the package name when it is missing.

| GPU | Driver file | Fedora | Debian/Ubuntu | Arch |
|---|---|---|---|---|
| NVIDIA (proprietary) | `nvidia_drv_video.so` | `nvidia-vaapi-driver` (RPM Fusion nonfree) | `nvidia-vaapi-driver` | `libva-nvidia-driver` |
| AMD (radeonsi) | `radeonsi_drv_video.so` | `mesa-va-drivers` | `mesa-va-drivers` | `libva-mesa-driver` |
| Intel (iHD, Gen8+) | `iHD_drv_video.so` | `intel-media-driver` | `intel-media-va-driver` | `intel-media-driver` |
| Intel (i965, legacy) | `i965_drv_video.so` | `libva-intel-driver` | `i965-va-driver` | `libva-intel-driver` |
| Nouveau (open NVIDIA) | `nouveau_drv_video.so` | `mesa-va-drivers` | `mesa-va-drivers` | `libva-mesa-driver` |
| Software (always) | — (bundled ffmpeg) | — | — | — |

`libva` itself is pulled in by the driver packages (`libva` on
Fedora/Arch, `libva2` on Debian/Ubuntu). NVIDIA also needs the proprietary
driver loaded (`nvidia_drm.modeset=1`); the VA-API driver is a userspace
bridge on top of NVDEC. Verify with `vainfo` after installing.

### Install commands (this section only; the app never runs these)

```bash
# Fedora (RPM Fusion nonfree must be enabled for NVIDIA)
sudo dnf install nvidia-vaapi-driver     # NVIDIA
sudo dnf install mesa-va-drivers         # AMD / Nouveau
sudo dnf install intel-media-driver      # Intel Gen8+

# Debian / Ubuntu
sudo apt install nvidia-vaapi-driver     # NVIDIA
sudo apt install mesa-va-drivers         # AMD / Nouveau
sudo apt install intel-media-va-driver   # Intel Gen8+

# Arch
sudo pacman -S libva-nvidia-driver       # NVIDIA
sudo pacman -S libva-mesa-driver         # AMD / Nouveau
sudo pacman -S intel-media-driver        # Intel Gen8+
```

## 4. Notes for the packaging phase

- **No NVENC / no proxy dependency**: recording falls back to x264 (CPU)
  and playback never transcodes — the only remux is a one-time
  `-c copy -movflags +faststart` to a cache copy (no re-encode, no GPU).
- **Wayland-only on Linux**: there is no X11 mode; the DMA-BUF renderer is
  enabled by default with a self-healing fallback (`dmabuf.state`), and
  software compositing switches the UI to low-power mode automatically.
- **Windows**: hardware decode ships with the GPU driver (D3D11/Media
  Foundation) — nothing to install.
- Tauri bundle `depends` (docs/08) covers the webview/appindicator floor;
  the generated table above is the complete engine truth for distro
  packaging.
